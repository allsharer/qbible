# qbible → Android: handback

**From:** the Claude agent that did the Android work in a sandbox, 2026-11-23/24.
**For:** the agent on the user's machine (fhdt), and the user.
**Branch:** `android` in `qbible/` (5 commits on top of `main` = `3261fe4` "Release 1.3.0"). Not pushed; remote unchanged.

## 1. Summary

- **A native Android app (Kotlin, Jetpack Compose) is built in `qbible/android/` and works on an Android 15 emulator.**
  Debug APK: `apk/qbible-android-0.1.0-debug.apk` (SHA-256 in `apk/SHA256SUMS`).
- It reads verses, ranges, chapters and whole books, moves to the previous or next chapter across book
  boundaries, and accepts every reference form the desktop accepts. Invalid references get the desktop's
  exact error message, and the app never jumps somewhere else.
- Search (words, phrases, exclusions, prefixes; all, any or exact phrase; whole Bible or one
  Testament; Bible or relevance order; counts and "Show more"; highlighting) gives the **same results in
  the same order as the desktop**. It also offers "Open John 3:16" when the search text is a reference.
- Bookmarks with labels and reading history use the desktop's schema and keys (`JHN.3.16-JHN.3.21`).
  A desktop `user.sqlite` opens unchanged. There is also JSON export and import.
- Settings: text size (14–32), serif or sans, line spacing, light/dark/system theme, supplied words as
  italics/[brackets]/plain, paragraphs or one verse per line, verse numbers on or off. You can copy or
  share a selected verse range, or the whole passage, with its reference.
- **No permissions at all** (no INTERNET), no network code, no adverts, analytics or accounts. Cloud backup is off.
- Tests: 25 Kotlin JVM tests, 12 instrumented tests on the emulator, and 128 Python tests. All pass.
  Details are in section 5. **It has never run on a real phone.**

## 2. What I did, and why

| Decision | Choice | Why |
|---|---|---|
| FTS5 or FTS4 | **FTS4**, rebuilt at build time (`android/tools/make_android_pack.py`) | Android's SQLite has no FTS5 (confirmed: the API 35 emulator has SQLite 3.44.3 **without FTS5**). FTS4 is always present, so no native library is needed (requery/sqlite-android would add several MB of native code per ABI plus a JitPack dependency). The FTS4 table holds each verse's tokens **exactly** as the FTS5 index has them: the script compares all 793,249 tokens with `fts5vocab` before writing, and the `simple` tokenizer then reproduces them on any device. All other tables are copied byte for byte. |
| FTS4 query syntax | Each term is one quoted `MATCH`, combined with SQL `INTERSECT` / `UNION` / `EXCEPT` | Whether FTS4 accepts `AND`/`NOT`/parentheses depends on a compile option (`SQLITE_ENABLE_FTS3_PARENTHESIS`) that differs between devices. A single quoted phrase (with `*` for a prefix) means the same in both syntaxes. User text still never reaches SQL: only `[a-z0-9]` tokens are used, as bound parameters. |
| Relevance order | FTS5's `bm25()` (k1 = 1.2, b = 0.75) recomputed in Kotlin from the same statistics | FTS4 has no `bm25()`, and `matchinfo` would not reproduce the desktop order. The Kotlin version matches the desktop's order exactly on every relevance case in the vectors. |
| Rules port | Pure Kotlin/JVM module `android/core` (no Android dependency) | Runs as plain JVM unit tests, and the app uses the same code. It reads `books.json` directly; the book list is not in code. Python's Unicode `\s`, `\d` and `\w` are written as explicit classes (`\p{Z}`, `\p{Nd}`, `[\p{L}\p{N}_]`) so the JVM and Android's ICU engine behave alike. |
| User data | Plain `SQLiteDatabase` with the desktop's migration SQL, **not Room** | It gives the identical file format (`schema_migrations`, the same timestamps), needs no annotation processor and is testable on the JVM. Room was allowed, but it would not have added anything here. |
| UI toolkit | Jetpack Compose + Material 3, single activity, one ViewModel | Current Android standard, and accessible by default (semantics, font scaling). Only `material-icons-core`, plus four simple icons drawn in code (the extended icon library is huge). |
| Minimum Android | **minSdk 26 (Android 8.0)**, target/compile SDK 35 | Covers nearly all phones in use, and adaptive icons and `java.time` are available. Only API 35 was tested. |
| Toolchain | AGP 8.7.3, Kotlin 2.0.21, Compose BOM 2024.12.01, Gradle 8.11.1 (wrapper), JDK 17 | A combination I know works together with JDK 17. These are about two years old; updating them is follow-up work. |
| Data in the APK | `books.json` and `kjv-android.sqlite` are **generated by Gradle** from the repo (`../qbible/resources/books.json`, `../build/translations/kjv.sqlite`), not committed | One source of truth. If the desktop pack is missing, Gradle runs `python3 -m qbible.build_data`. The pack is copied out of the APK once (after each install or update) and opened read-only. |
| Whole book | `gen` opens **all of Genesis** with chapter headings (like the CLI). The Books screen offers chapters or the whole book | The handover asks for "verse, range, chapter or whole book". The browser opens chapter 1 for a bare book name. Say if you prefer that. |
| Backups | Cloud backup excluded; device-to-device transfer includes `user.sqlite` and settings; JSON export and import in Settings | The prompt says reading history must not go to an external service. Without any backup, though, bookmarks would be lost when changing phones. |
| App id / version | `org.qbible.app` (**placeholder**), versionName `0.1.0`, versionCode 1 | **You must confirm the id before publishing**: it can never change after a Play release. |

Bug found only on a device: Android's ICU regex engine rejected the reference-detection pattern
`(?![\p{L}\p{N}_:])` ("Incorrect Unicode property"). That stopped `Reference.kt` from loading, although
every JVM test passed. The fix is the same set written `[_:\p{L}\p{N}]`, and the full differential
suite now also runs on the device. Older Android versions have older ICU, so they need testing (see section 6).

## 6. Not done or not tested

- **Never run on a real phone.** It was tested only on an API 35 x86_64 emulator. **Android 8–14
  (API 26–34) is untested.** Their older SQLite and ICU versions could differ, as the ICU regex bug
  above shows. Running `./gradlew connectedDebugAndroidTest` on an old phone or an API 26/29 emulator
  would cover this: the differential suite checks every rule on the device.
- **TalkBack was not tested** (the AOSP emulator image I used does not include it), and there were no automated
  accessibility checks. What is in place: content descriptions on all icon buttons, headings,
  live-region errors and search status, radio and switch roles, 48 dp touch targets, sp text that
  follows the system font size, and colours chosen for high contrast. In paragraph layout, TalkBack
  selects verses through per-verse custom actions. "One verse per line" is probably easier with
  TalkBack and is labelled as such.
- Not exercised on a device: **copy to clipboard and the share sheet** (the copied text is unit-tested),
  **Export/Import through the file picker** (the JSON logic is unit-tested), restoring the scroll
  position after a restart, device-to-device transfer and the backup rules, landscape and tablet
  layouts, and editing or removing bookmark labels from the Saved screen.
- Not signed with a real key; there is no Play listing, no store graphics and no privacy-policy page.
  The launcher icon is a placeholder I drew.
- Small known issues:
  - The splash screen follows the phone's theme, not the app's.
  - The reader's subtitle is the fixed text "King James Version", not read from the pack.
  - Relevance search on very common words is the slowest operation.
  - System fonts only (no bundled reading font).
- **The JSON export format is new.** The desktop cannot read it yet. A `qbible import-userdata` /
  `export-userdata` on the desktop would complete the round trip.
- Translation picker: the app bundles only the KJV. The core handles any schema-1 pack converted with
  the script, but there is no UI to choose one.
- I noticed one desktop quirk and left it alone: `UserStore.add_bookmark` called with an *unresolved*
  open range (`Mark 4:1-`) stores `MRK.4.1-MRK.4`. The CLI and server always resolve first, so users
  cannot reach it.
- Sandbox-only setup, not part of the deliverable: I installed the Android SDK in `~/android-sdk`,
  added a swap file and opened up `/dev/kvm` to run the emulator.

## 7. How to build and install (Ubuntu)

These steps are also in `qbible/android/README.md`.

```sh
sudo apt install openjdk-17-jdk python3 unzip
# Android command-line tools from https://developer.android.com/studio#command-line-tools-only
mkdir -p ~/android-sdk/cmdline-tools && cd ~/android-sdk/cmdline-tools
unzip ~/Downloads/commandlinetools-linux-*_latest.zip && mv cmdline-tools latest
yes | ~/android-sdk/cmdline-tools/latest/bin/sdkmanager --licenses
~/android-sdk/cmdline-tools/latest/bin/sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"

cd ~/ai-shared/bibleApp/qbible && git checkout android      # or wherever you merge it
mkdir -p build/translations && cp ../prebuilt/kjv.sqlite build/translations/   # optional; Gradle builds it if missing
python3 -m unittest discover -s tests -t .                  # expect: Ran 128 tests ... OK

cd android
echo "sdk.dir=$HOME/android-sdk" > local.properties
./gradlew :core:test                    # Kotlin JVM tests
./gradlew assembleDebug                 # -> app/build/outputs/apk/debug/app-debug.apk
~/android-sdk/platform-tools/adb install -r app/build/outputs/apk/debug/app-debug.apk
./gradlew connectedDebugAndroidTest     # phone (USB debugging on) or emulator attached
```

Or install the prebuilt APK: enable USB debugging on the phone, then run
`adb install apk/qbible-android-0.1.0-debug.apk`, or copy the file to the phone and allow installs
from that source. It is signed with the sandbox's Android **debug** key, so before installing a build
from your own machine you must uninstall it (`adb uninstall org.qbible.app`), which **deletes its
bookmarks**. Export them first.

The first build downloads Gradle 8.11.1 and the dependencies (about 1 GB). With little RAM, close
other programs; `gradle.properties` sets a 1.5 GB heap.

**Release signing** (nothing is set up, and there are no keys in the repo):
1. Create an upload key outside the repo and back it up:
   `keytool -genkeypair -v -keystore ~/keys/qbible-upload.jks -alias qbible -keyalg RSA -keysize 4096 -validity 10000`
2. `./gradlew bundleRelease` (AAB for Play) or `./gradlew assembleRelease` (APK, R8-shrunk).
3. For an APK: `zipalign -p 4 app-release-unsigned.apk aligned.apk`, then
   `apksigner sign --ks ~/keys/qbible-upload.jks --out qbible.apk aligned.apk` (tools in `~/android-sdk/build-tools/35.0.0/`).
   For Play: sign the AAB with the upload key (`jarsigner`) and enrol in Play App Signing.
4. Alternatively, add a `signingConfigs` block that reads the paths and passwords from `~/.gradle/gradle.properties` or the environment. Never commit them.

## 8. Questions for the user

1. **App name and id.** Keep "qbible" and `org.qbible.app`, or choose an id under a domain you control
   (e.g. `uk.yourname.qbible`)? The id is permanent once published.
2. **Distribution.** Google Play, F-Droid, or sideloading only? Play needs a developer account, a
   privacy policy (it can say "collects nothing") and `targetSdk` raised to Play's current
   requirement (probably 36 by now). F-Droid fits the no-tracking aim and builds from source.
3. **Minimum Android version.** Is 8.0 (API 26) right? Can you test on your oldest phone?
4. **Icon.** Keep the placeholder open book or supply one? (The desktop has its own icon renderer,
   `tools/render-icons.mjs`; I did not reuse it.)
5. **A bare book name** (`gen`): open the whole book (current, as in the CLI) or chapter 1 (as in the browser)?
6. **UK distribution.** The KJV text carries the Crown's printing rights in the UK (see
   `THIRD_PARTY_NOTICES.md`). Does an app store listing need a check for UK users?
7. Should the desktop get JSON **import/export** of bookmarks and history, so phone and desktop can
   exchange them? A later sync could build on the same keys.
